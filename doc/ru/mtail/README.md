# Модуль Mtail в Alligator

В этом документе описан новый модуль `mtail` в Alligator.

Модуль реализован в `src/amtail` и использует встроенную библиотеку `amtail` из [amtail](https://github.com/alligatormon/amtail). Он предоставляет модель выполнения, аналогичную Google mtail, для преобразования строк логов в метрики непосредственно внутри кодовой базы Alligator на C.

## Что делает модуль

- Компилирует программы mtail из файлов (скрипты `.mtail`)
- Сохраняет скомпилированные программы как именованные контексты
- Обрабатывает входящие строки логов выбранной программой
- Поддерживает состояние парсера для каждого контекста между строками
- Экспортирует счётчики/гauges/гистограммы как обычные метрики Alligator
- Опционально — **преобразованные логи** через `emit_log(...)`, если у aggregate/entrypoint задан `log_channel_out` (расширение Alligator; не входит в stock mtail)

## Модель выполнения

Есть две основные части:

1. **Реестр программ** (контексты `mtail`):
2. **Путь приёма логов** (`entrypoint` с `handler mtail`):
   - Входные данные разбиваются по символу новой строки
   - Каждая полная строка выполняется в VM
   - Незавершённые хвосты строк буферизуются и дописываются к следующему фрагменту
   - Переменные VM преобразуются в метрики Alligator
   - Полный экспорт переменных (для обновления **TTL** метрик на неактивных сериях) выполняется при первом фрагменте и затем не реже, чем раз в **`mtail_full_export_interval`** секунд; между этими моментами экспортируются только затронутые переменные (см. [конфигурацию mtail](configuration.md#mtail_full_export_interval))

## Как выбирается скрипт

При обработке входного потока:

1. Если задан `entrypoint.mtail`, это значение используется как имя программы.
2. Если именованный контекст не найден, но `entrypoint.mtail` задан, Alligator пытается выполнить ленивую загрузку по этому имени и пути к скрипту.
3. Если контекст по-прежнему не найден, используется любой доступный загруженный контекст mtail.
4. Если скомпилированного скрипта нет, разбор этого payload завершается ошибкой.

## Метки (labels)

Если переменная mtail использует `by ...`, модуль формирует метки из ключа переменной.

Текущая реализация поддерживает:

- постоянные значения меток
- подстановки переменных (например, `$httpcode`), разрешаемые из переменных VM

Это позволяет скриптам mtail создавать многомерные метрики, отображаемые как обычные метрики Alligator с метками.

## emit_log (преобразованные логи)

Расширение Alligator (не stock Google mtail). При `log_channel_out` на aggregate:

```
counter lines_total

/error=(?P<msg>.*)/ {
  lines_total++
  emit_log($msg)
}
```

`emit_log` отправляет подготовленную строку в `log_channel_out`. Без вызова экспортируются только метрики.

## Потокобезопасность

У каждого загруженного контекста mtail есть свой mutex.
Выполнение одного контекста сериализуется этой блокировкой, чтобы состояние байткода и буферизация хвостов строк оставались безопасными.

## Логирование и отладка

Контекст mtail поддерживает уровни логирования для отдельных стадий:

- `log_level_parser`
- `log_level_lexer`
- `log_level_generator`
- `log_level_compiler`
- `log_level_vm`
- `log_level_pcre`

Кроме того, если уровень логирования entrypoint — debug, Alligator может выводить переменные VM mtail во время обработки.

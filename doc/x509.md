# X509 certificate collector 
X509 is a list of configurations used to check certificates on filesystem. This option can be used multiple times in the configuration file.\
This option starts recursively walking through directories to find all files that match the `match` option (or a basename glob in `path`) and tries to parse them.

## Overview
```
x509
{
    name first_context;
    path /etc/ssl;
    match .crt;
    period 60s;
    add_label source:nginx;
}
x509
{
    name second_context;
    path /etc/nginx;
    match .pem;
}
x509
{
    name path_glob;
    path /etc/ssl/*.pem;
}
x509
{
    name third_context;
    path /etc/kafka;
    match .jks;
    type jks;
    password jkspass;
}
```

## name
Specifies only the context name.\
This does not affect anything in the context of collecting metrics; it is solely a key used to update fields of the x509 context by the Alligator API.

## path
Specifies the starting path to recursively parse and walk through the directories to find certificates.

If the **basename** of `path` contains a glob (`*`, `?`, or `[...]`), alligator splits it like the aggregate file reader: the directory is crawled and the basename becomes the match pattern when `match` is omitted. Example: `path /etc/ssl/*.pem` crawls `/etc/ssl` with pattern `*.pem`. Mid-path globs (`/a/*/b.pem`) and recursive `**` are not supported. When both a basename glob in `path` and an explicit `match` are set, `match` wins and the path is still truncated to the directory.

## match
Filters which files are treated as certificates.

- Patterns **without** glob characters use a substring match on the full file path (legacy behavior), e.g. `match .crt`.
- Patterns **with** `*`, `?`, or `[...]` use `fnmatch(3)` against the **basename** only, e.g. `match *.pem`.

`match` may be omitted when `path` includes a basename glob. Otherwise `match` is required.

## except
Optional list of patterns that exclude files even when they match `match`. Uses the same hybrid rules as `match` (substring without globs, `fnmatch` on basename with globs).

Typical use: collect `*.pem` but skip private keys:

```
x509 {
    name nginx-certs;
    path /etc/nginx/ssl/*.pem;
    except *_key.pem _key.pem;
}
```

Empty `except` skips nothing. Checked before `match`.

## period
Specifies the period of time to repeatedly parse certificates in the context. The default value is `10s`.

More information about units that user can specify in configuration can be obtained from configuration [doc](https://github.com/alligatormon/alligator/blob/master/doc/configuration.md).

## type
Possible values:
- pem
- jks
- pfx

This option can control the method used to parse certificate files for this context. The default value is `pem`.

## password
Specifies the passphrases to open PFX/JKS archives.

## ca_file
Optional path to a PEM CA bundle (or single CA) used to verify the certificate chain for filesystem PEM/PFX checks.
Without `ca_file`, filesystem collection only checks time validity (`notBefore`/`notAfter`).
Hostname/CN/SAN matching is not done for filesystem checks (only for network TLS probes).

## crl_file
Optional PEM (or DER) CRL used to mark filesystem certificates as revoked (`x509_cert_valid{reason="revoked"}`).

## crl_scope
`leaf` (default) checks only the end-entity certificate. `chain` also requires CRLs for intermediates (`X509_V_FLAG_CRL_CHECK_ALL`).

## ocsp
`on` enables an OCSP request using the AIA URL from the certificate, or `ocsp_responder` if set. Filesystem checks always fetch inline.

## ocsp_responder
Override the OCSP URL from the certificate AIA (`http://` or `https://`).

## ocsp_proxy
HTTP or SOCKS5 proxy used only for the OCSP fetch (`http://`, `socks5://`, `socks5h://`). Independent of any scrape `proxy=`.

## ocsp_timeout
OCSP HTTP timeout. Default `3s`.

## ocsp_cache_ttl
Upper bound for the OCSP result cache. Default `1h`. The cache also honors `nextUpdate`.

## revocation_mode
`soft` (default): responder/CRL-load errors do not fail the check; a revoked answer always fails.
`hard`: unknown/error/no-responder also fail.

## Examples of use

### For monitoring PEM certs
```
x509
{
    name nginx-certs;
    path /etc/letsencrypt/live;
    match .crt;
}
```

### For monitoring PEM certs with chain/CA verification
```
x509
{
    name nginx-certs;
    path /etc/letsencrypt/live;
    match .crt;
    ca_file /etc/ssl/certs/ca-bundle.crt;
}
```

### For monitoring PEM certs with CRL and OCSP
```
x509
{
    name nginx-certs;
    path /etc/letsencrypt/live;
    match .crt;
    ca_file /etc/ssl/certs/ca-bundle.crt;
    crl_file /etc/ssl/ca.crl;
    ocsp on;
    ocsp_responder http://ocsp.example.com/;
    ocsp_proxy http://proxy:3128;
    revocation_mode soft;
}
```

### For monitoring JKS certs
```
x509
{
    name kafka-certs;
    path /etc/kafka/;
    match .jks;
    type jks;
    password 123456789;
}
```

### For monitoring PFX certs
```
x509 {
    name pfx;
    path /app/src/tests/certs;
    match .pfx;
    password 123456;
    type pfx;
}
```

## add_label
Attaches extra labels at ingest for filesystem PEM/PFX (and JKS lang) metrics. Collector labels (serial, issuer, …) win if a key already exists. Metric **name** rewrite stays on the Prometheus entrypoint scrape, not inside `x509`.

```
x509 {
    name nginx-certs;
    path /etc/letsencrypt/live;
    match .crt;
    add_label source:nginx;
    metricstransform {
        include ^x509_cert_.*$ match_type regexp label serial regex '^(.*)$' replacement '$1';
    };
}
```

## metricstransform
Same native block / JSON as on [aggregate](aggregate.md) and [action](action.md). Applied at ingest for this x509 context.
